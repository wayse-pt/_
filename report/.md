## 17. Processing of non-existent HTTP target resources
<a name='§I.17'></a>
### 17.1
<a name='§I.17.1'></a>
#### 17.1.1
<a name='§I.17.1.1'></a>
If the origin server of the Lovable hosting (`p.l5e.io`) considers a non-existent target resource a file, then it returns `HTTP 404` («Not Found»).
#### 17.1.2
<a name='§I.17.1.2'></a>
The origin server of the Lovable hosting qualifies the target resource as a file by the presence of a dot in the final path segment of the target resource URL.
### 17.2
<a name='§I.17.2'></a>
If the origin server of the Lovable hosting does not consider a non-existent target resource a file, then it returns `HTTP 200` («OK») and the HTML skeleton **[§3.2](#§I.3.2)**.
### 17.2.1
<a name='§I.17.2.1'></a>
For the website, the **[§17.2](#§I.17.2)** case is implemented, in particular, for the routes **[§12.3.2](#§I.12.3.2)**.
### 17.3
<a name='§I.17.3'></a>
Lovable does not document the behavior **[§§17.1-17.2](#§I.17.1)**: I established this behavior empirically.

<a name='§I.22.5'></a>
